* Samsung Exynos specific extensions to the Synopsys Designware Mobile
  Storage Host Controller

The Synopsys designware mobile storage host controller is used to interface
a SoC with storage medium such as eMMC or SD/MMC cards. This file documents
differences between the core Synopsys dw mshc controller properties described
by synopsys-dw-mshc.txt and the properties used by the Samsung Exynos specific
extensions to the Synopsys Designware Mobile Storage Host Controller.

Required Properties:

* compatible: should be
	- "samsung,exynos4210-dw-mshc": for controllers with Samsung Exynos4210
	  specific extensions.
	- "samsung,exynos4412-dw-mshc": for controllers with Samsung Exynos4412
	  specific extensions.
	- "samsung,exynos5250-dw-mshc": for controllers with Samsung Exynos5250
	  specific extensions.
	- "samsung,exynos5420-dw-mshc": for controllers with Samsung Exynos5420
	  specific extensions.
	- "samsung,exynos7-dw-mshc": for controllers with Samsung Exynos7
	  specific extensions.
	- "samsung,exynos7-dw-mshc-smu": for controllers with Samsung Exynos7
	  specific extensions having an SMU.

* samsung,dw-mshc-ciu-div: Specifies the divider value for the card interface
  unit (ciu) clock. This property is applicable only for Exynos5 SoC's and
  ignored for Exynos4 SoC's. The valid range of divider value is 0 to 7.

* samsung,dw-mshc-sdr-timing: Specifies the value of CIU clock phase shift value
  in transmit mode and CIU clock phase shift value in receive mode for single
  data rate mode operation. Refer notes below for the order of the cells and the
  valid values.

* samsung,dw-mshc-ddr-timing: Specifies the value of CUI clock phase shift value
  in transmit mode and CIU clock phase shift value in receive mode for double
  data rate mode operation. Refer notes below for the order of the cells and the
  valid values.
* samsung,dw-mshc-hs400-timing: Specifies the value of CIU TX and RX clock phase
  shift value for hs400 mode operation.

  Notes for the sdr-timing and ddr-timing values:

    The order of the cells should be
      - First Cell: CIU clock phase shift value for tx mode.
      - Second Cell: CIU clock phase shift value for rx mode.

    Valid values for SDR and DDR CIU clock timing for Exynos5250:
      - valid value for tx phase shift and rx phase shift is 0 to 7.
      - when CIU clock divider value is set to 3, all possible 8 phase shift
        values can be used.
      - if CIU clock divider value is 0 (that is divide by 1), both tx and rx
        phase shift clocks should be 0.

* samsung,read-strobe-delay: RCLK (Data strobe) delay to control HS400 mode
  (Latency value for delay line in Read path)

Exynos7885/7904 vendor-compatible bring-up:

* compatible: "samsung,exynos-dw-mshc" selects the vendor 64-bit register
  layout (CLKSEL at 0xa8), not the older Exynos4/5 layout. This initial port
  supports legacy and high-speed SDR only; do not enable DDR, HS200, HS400,
  enhanced strobe, command queueing or inline encryption capabilities.
* clocks / clock-names: use "biu" for the compound GATE_MMC_EMBD gate and
  "ciu" for UMUX_CLKCMU_FSYS_MMC_EMBD, the actual card input rate. The
  vendor's "ciu_gate" name is not consumed by the 5.10 core. CMU rates
  remain firmware-owned; the core's CLKDIV divides the measured input.
* mmc-exynos-smu: phandle to a node compatible with "samsung,exynos-smu".
  The host calls the vendor secure-firmware service directly, selecting
  standard non-FMP descriptors (type 0), then initializing/resuming SMU.
  Firmware errors fail probe/resume; no guessed protected MMIO writes or
  encryption key operations are performed.
* samsung,dw-mshc-ciu-div: mandatory divider (0..7), matching both timing
  properties' first cells.
* samsung,dw-mshc-sdr-timing / samsung,dw-mshc-ddr-timing: exactly FOUR
  cells, in vendor order: divider (0..7), fine drive (0..3), drive (0..7),
  sample (0..7). The divider is CLKSEL[26:24], fine drive [23:22], drive
  [18:16], sample [2:0]. These are not upstream's two-cell tuples.

The address windows (0x13500000/0x2000, 0x13508000/0x200), IRQ 146,
SMU reference and vendor clock IDs are from Samsung 4.4
arch/arm64/boot/dts/exynos/exynos7885.dtsi:770-794. The existing CMU
provider implements GATE_MMC_EMBD and UMUX_CLKCMU_FSYS_MMC_EMBD;
no invented fixed clock or new CMU register programming is used.

The m20lte values come from Samsung 4.4
arch/arm64/boot/dts/exynos/exynos7904-m20lte_common.dtsi:477-525:
SDR <3 0 4 0>, DDR <3 0 4 2>, divider 3, FIFO depth 0x40, bus width 8.
The original reference-clock table at lines 507-508 is (MHz):
25 50 50 25 50 100 200 50 50 200 200 200. This port caps card frequency
at its high-speed entry (50 MHz), without pretending those CMU reference
rates can yet be programmed. HS200/HS400 timings and delay lines are
present in the source but deliberately deferred, not missing/guessed.
Timing packing and the identification-clock phase-7 disable come from
4.4 drivers/mmc/host/dw_mmc-exynos.h:123-180,283-295 and
4.4 drivers/mmc/host/dw_mmc-exynos.c:298-309,489-572,679-697.
SMU call order/arguments are from 4.4 drivers/mmc/host/dw_mmc.c:4513-4530,
4855-4864, drivers/mmc/host/dw_mmc-exynos-smu.c:105-144,
drivers/crypto/fmp/smu_dev.c:29-89, include/crypto/smu.h:15-37,
and include/linux/smc.h:43-48. The firmware path is used instead of the
no-SMU fallback's direct partition-0 bypass register writes.

Required properties for a slot (Deprecated - Recommend to use one slot per host):

* gpios: specifies a list of gpios used for command, clock and data bus. The
  first gpio is the command line and the second gpio is the clock line. The
  rest of the gpios (depending on the bus-width property) are the data lines in
  no particular order. The format of the gpio specifier depends on the gpio
  controller.
(Deprecated - Refer to Documentation/devicetree/bindings/pinctrl/samsung-pinctrl.txt)

Example:

  The MSHC controller node can be split into two portions, SoC specific and
  board specific portions as listed below.

	dwmmc0@12200000 {
		compatible = "samsung,exynos5250-dw-mshc";
		reg = <0x12200000 0x1000>;
		interrupts = <0 75 0>;
		#address-cells = <1>;
		#size-cells = <0>;
	};

	dwmmc0@12200000 {
		cap-mmc-highspeed;
		cap-sd-highspeed;
		broken-cd;
		fifo-depth = <0x80>;
		card-detect-delay = <200>;
		samsung,dw-mshc-ciu-div = <3>;
		samsung,dw-mshc-sdr-timing = <2 3>;
		samsung,dw-mshc-ddr-timing = <1 2>;
		samsung,dw-mshc-hs400-timing = <0 2>;
		samsung,read-strobe-delay = <90>;
		bus-width = <8>;
	};
